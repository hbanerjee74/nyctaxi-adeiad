# VD-7140 verification

Five findings from the VD-7126 validation review: three population bindings in the canonical trips model and two grain disagreements.

## Rulings

| Finding | Ruling | Where it lives |
| --- | --- | --- |
| Band profile bound `trip_count` on a table whose inner joins dropped refunds and negative durations | Repair the mart: LEFT band joins, `unbanded` sentinel, LEFT dimension joins for null zone keys (ADR 0015) | `agg_trip_band_profile.sql`, `assert_aggs_cover_every_trip` |
| Weather profile bound `trip_count` on a weather-driven spine covering six boroughs | Repair the mart: borough × day spine, as-of zone attribution (ADR 0009), optional weather, `unresolved` group (ADR 0012) | `agg_weather_demand_daily.sql`, `assert_aggs_cover_every_trip` |
| OD matrix bound star metrics on a `>= 25` truncated table | Record the floor as a business rule and keep the bindings, with the narrower population stated in the ADR | ADR 0017, `agg_od_flow_matrix.md`, source `note`, `assert_od_flow_floor` |
| `dim_fare_regime` grain disagreed with `_core.yml` | The table is not SCD2: unique per `(fare_component, applies_to_fleet, valid_from_date)`, keyed by the unique regime code | `nyc_taxi_fare_regime.ossie.yaml`, `_core.yml` |
| `bridge_zone_poi` described many-to-many while `poi_id` is tested unique | Zone → POI is one-to-many; wording corrected in the mart, `_core.yml` and the model | `bridge_zone_poi.sql`, `_core.yml`, `nyc_taxi_zone_poi.ossie.yaml` |

## Measured, and not

The two singular tests ran against a built warehouse during review: `assert_aggs_cover_every_trip` passed for both profiles, and the band profile summed to the fact count with 500 unbanded rows over 35,808 trips; the weather profile produced 819 borough-days, 273 of them with null weather. `dbt build` and `dbt test` are not part of the local gate, so CI must keep holding them.

Not verified: `sqlfluff` (not installed here); dbt Semantic Layer runtime parity (read, not executed; the layer is since retired).
