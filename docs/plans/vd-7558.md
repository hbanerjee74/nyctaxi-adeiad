# Reference Domain skills name the retired ossie.py test commands Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every instruction in the reference Domain's seeded semantic-model skills names an `ossie.py` command that exists, so following it regenerates the generated dbt tests instead of failing.

**Architecture:** Documentation correction only. `a92bd64` (VD-7541) consolidated `ossie.py level-tests` and `ossie.py content-tests` into `ossie.py generate-tests <model-dir> <tests-dir> [--check]`, which writes `assert_semantic_content_holds.sql`, `assert_semantic_level_keys_hold.sql` and `assert_semantic_levels_hold.sql`. Eleven instructional mentions across seven seeded files still name the removed commands. The replacement text follows the plugin's current wording (`accelerate-data/vibedata-data-engineering`, `origin/main`), so the next skill refresh corrects wording rather than commands.

**Tech Stack:** Markdown skill files, `ossie.py` (Typer), pytest, ruff.

**Spec:** VD-7558 (Linear); `docs/functional/intent/README.md` and `docs/design/data-platform/ossie-canonical-artifacts.md` § Gates in `accelerate-data/studio`.

## Global Constraints

- Replacement command form, verbatim: `ossie.py generate-tests <model-dir> <tests-dir>`, and `ossie.py generate-tests <model-dir> <tests-dir> --check` where the point is detecting a stale or missing file.
- The three files `generate-tests` writes: `assert_semantic_content_holds.sql`, `assert_semantic_level_keys_hold.sql` (severity `error`), `assert_semantic_levels_hold.sql` (severity `warn`).
- Keep the version-history row in `semantic-model/references/vibedata-fields.md` historical: it keeps `added \`ossie.py level-tests\`` and adds the plugin's `(since merged into \`generate-tests\`)`, so no reader can copy a dead command from it.
- No behavior change in `ossie.py`; no generated test file may change.
- One concern, one commit: a single `docs:` commit after every task passes.
- Do not refresh the seeded skills wholesale from the plugin — wording only where this plan names it.

## Review Focus

- A reader who follows a replacement literally must reach the real command; `<model-dir>` and `<tests-dir>` stay placeholders, as every other command in these skills does.
- A sentence that claims which test holds a declaration must name the test the current `generate-tests` actually writes, or it trades one wrong instruction for another.
- `checks.md` must not describe two commands that no longer exist as separate rows.

## Amendments after review

The independent quality gates and the AI PR review changed the wording below after the first pass; the tasks above are otherwise as executed. Where a task's quoted replacement differs from the committed file — Task 1 Step 3, Task 2 Step 2, and Task 3 Steps 2 and 3 — these bullets record the final wording and the files are authoritative.

- `semantic-model/SKILL.md` compiler sentence names the content test's generation rather than "the generated tests": `ossie_levels.py` imports no compiler, so only the content test is generated from it.
- `semantic-model/SKILL.md`'s level sentence carries the plugin's routing rule: a reported row is a data finding, and a failing key is fixed in the mart, never by weakening the level.
- `validating-semantic-model/SKILL.md` item 4a names **both** level tests and no longer implies `--check` regenerates; `--check` writes nothing.
- `reverse-engineering.md` describes the content comparison group by group at the source's content levels (not "totals"), and fixes in the mart what `assert_semantic_level_keys_hold` reports while recording `assert_semantic_levels_hold`'s rows as data findings.
- `vibedata-fields.md`'s `1.3` row gains the plugin's `(since merged into \`generate-tests\`)`.
- `checks.md`'s `generate-tests` row uses the same group-by-group description, keeps the plugin's SUM and decimal tolerance sentence, and joins its two limits with a semicolon.
- `workarounds/SKILL.md` says "regenerate the tests", not "regenerate the generated tests".
- Rejected: a repo-wide guard test that fails when a skill names a nonexistent `ossie.py` subcommand. It is a new lint with its own home and test-map registration; recorded in VD-7558 as a follow-up instead. Rejected: dropping "the declaration stays the intent" from `vibedata-fields.md`, which the plugin carries and which states the rule the warn severity encodes.
